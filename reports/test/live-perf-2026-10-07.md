# Live site performance test — dearmydiary-eight.vercel.app

Date: 2026-10-07. Branch tested: `main` as deployed (NOT PR #4).

Tooling: repo's own Playwright harnesses (`measure-perf.mjs`, `measure-routes.mjs`) plus a
headless Chromium 153 driven through Chrome DevTools MCP (Lighthouse, console, network,
DOM, CPU-throttled interaction probes).

## Headline

The site is healthy functionally — zero console errors on every route, CLS 0.0000, no
layout overflow, Best Practices 100. The weak spots are first-paint weight on a slow
mobile link (LCP 3.9 s), the `/write` editor's per-keystroke main-thread cost (~250 ms per
keystroke at 4x CPU on the deployed bundle), and one small ARIA violation on the bookmark
element.

Important context: production still serves the stale entry chunk `index-CMOU4_Uy.js`,
built before the P0/P1 merge (b60aa5d) and before PR #4. Every "deployed bundle is slower"
number below reflects code that is already fixed on `fix/audit-p2` but not shipped. The
deploy blocker itself (host environment variables not reaching the Vercel build) is still
open — see `reports/audit/next-deploy-blocker.md`.

Failed audits, all small:

| Audit | Finding | Fix |
|---|---|---|
| `aria-prohibited-attr` | `<span aria-label="Your place in the book" ...>` — `aria-label` is prohibited on a generic `span` with no ARIA role | give the bookmark `role="img"` (or move the label to a visually hidden text node) in `src/components/book/CoverBookmark` |

| `llms-txt` | `/llms.txt` same story (missing H1/links) | optional; same one-file fix |
| `agent-accessibility-tree` | tooling artifact of the same fallback page | n/a |

Not found in the Lighthouse pass but known from the audit: the nested `<Link><Button>`
double tab stops and the mood-label contrast failures are fixed in PR #4 and will clear
when it ships.

## 5. Editor keystroke cost on the deployed bundle (the real code-perf gap)

Same harness as the local audit (real keyboard events, 20 keystrokes 40 ms apart, 4x CPU):

```
deployed (stale) bundle   totalLongTasks = 5040 ms   worst = 524 ms   ~250 ms per keystroke
local build (PR #4)       totalLongTasks = ~2800 ms  worst = ~350 ms  ~130 ms per keystroke
```

So the fixes already on the PR roughly halve the per-keystroke block, and the remaining
cost is ProseMirror's own update plus React re-rendering the composer — the part the
audit flagged as needing a larger refactor (memoizing the sidebar, keeping the editor
body out of the re-render path). On the deployed bundle the editor is noticeably laggy on
a mid-range device; locally it is merely noticeable.

## Recommended order

1. Ship PR #4 (already verified) — theme flash gone, error contrast AA, no nested tab
   stops, halved editor cost, warm dashboard route, preloaded cover fonts.
2. Fix the deploy blocker (human, Vercel dashboard) so any of this actually reaches
   production.
3. Add `public/robots.txt` (one file, clears the SEO audit).
4. Give the bookmark element a valid ARIA role (one line, clears the a11y audit).
5. Bigger levers, needs a decision: subset the two decorative fonts (LCP), and
   memoize/split the composer so `/write` stops re-rendering the whole page per keystroke.
